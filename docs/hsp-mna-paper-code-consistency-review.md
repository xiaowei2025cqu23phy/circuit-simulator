### 投稿风险排序

1. **高风险—可复现代码路径与所报告 GitHub 源码不是同一份文件。** ZIP 内脚本以相对路径导入 `bench_workspace/src/sim/{linearSolve,rankOneUpdate}.js`，但这两份是从研究分支拷贝的快照，不是报告中路径所暗示的仓库源文件。对比快照和当前分支发现算法计算主体相同，但有注释/格式差异；需把具体 commit、源文件 SHA-256 与复现环境固定并在归档中保存。审查时使用打包脚本原路径（`bench_workspace/scripts`）成功重跑，避免把快照放在其他目录导致的模块路径错误。
2. **高风险—RHS 工作量措辞有实质性小偏差。** 脚本先构造初始矩阵并做初始分解/求逆，随后对每个 24 次事件更新后才解 RHS；初始矩阵没有对应 RHS 求解。因此数据确实有 25 次完整分解、24 次更新后状态、`24 × R` 次线性求解（R=8 时为 192），但“每个状态都有 R 个 RHS”的精确理解会变成 `25 × R`。应改为“每次更新后的矩阵状态求 R 个右端，初始状态仅做准备分解/求逆”。同样，式 (8.3) 应定义 K 为事件后求解的矩阵状态数，或显式加入初始状态 RHS 项，避免与计数混淆。
3. **高风险—主论文早期独立 Python 单节点结果和第八轮 Node 基准是不同证据链。** 主文明确说 Python 实现独立，不是仓库引擎；ZIP 文件清单没有列出文中称随稿提供的 `hsp_mna_reproduce.py`、`benchmark_modes.py`、其结果 CSV 或对应 Python 依赖锁定文件。第八轮 Node 复现包则提供 benchmark 与 MNA CSV。应补齐主文 Python 原始脚本、依赖版本、数据/事件匹配细节；若它们另有交付位置，稿件应给出长期可访问的精确存档链接。
4. **中高风险—RHS=1/32 的“排序反转”已由原始数据支持，但独立进程复查批次数有限且失败样本不完整。** 原始汇总和复现批次一致支持方向，当前 Windows Node v26 复跑也再次出现同方向；然而论文环境是共享 Debian/EPYC Node v22，Windows 复跑不能替代该环境的原始数据，也不能提高原始跨进程重复数。应称为“这些配置/批次观察到排序改变”，不要估计普适交叉点或声称重复得到相同绝对时间。
5. **中风险—论文插图文件名未与材料包索引对齐。** Markdown 技术附录引用 `figures/f8_01.png` 至 `figures/f8_05.png`，但 ZIP 实际文件名为 `F8_01_Node矩阵规模计时.png`、`F8_02_右端数量的策略反转.png` 等，大小写、命名和扩展标识均不对应。若 Markdown 是复现/发布源，应修正引用或添加一致命名的副本，并测试从干净解压目录构建 PDF；现有 PDF 内嵌图像本身仍可读。

## 四、数学与算法细节

### 4.1 秩一更新的右端项边界

若二端支路电流写为 `i=g(v_p−v_q)−I_0`，A 的支路增量确为 `Δg aaᵀ`。若状态改变还使偏置电流 `I_0` 改变，右端亦随之改变（符号取决于文中电流与 RHS 约定，论文第七轮附录给出 `b_new=b+ΔI_eq a`）。第八轮合成实验明确仅测 A 的线性代数成本、每状态人为给出 RHS，故数学公式正确但它不测试完整二极管 ON/OFF 电流印记切换。

### 4.2 Sherman–Morrison 数值保护的含义

分母非零是精确公式可逆的必要代数条件；浮点运算中“非零”不足以保证稳定。代码的相对分母门限是工程启发式，且会把无法接受的更新退回完整求逆。桥式 guard 消融数据支持此实现策略的实际价值，不足以推导一个通用最优阈值、条件数上界或对任意病态网络安全的结论。性能图表应包含回退发生率；合成 benchmark 零回退是该温和构造的观察，不反驳整流桥失败案例。

### 4.3 时间步源采样与参考解

BE-end 是受迫后向欧拉标准时间层的一致取样约定。仓库保留 `legacy-start` 为兼容默认；论文第六轮修订对此说明正确。对比算法精度应固定 sourceSampling、初始条件、状态机与时间网格。BE-end 1 µs 细网格仍是同一 PWL 模型的数值近似参考，不是连续解的严格误差界，也不是 Shockley/ngspice 物理真值。

## 七、发现/不一致项及建议修订

1. **RHS 数量定义（必须改）**：基准循环中初始 A 只分解/求逆、不解 RHS，之后 24 个导纳变化各解 R 个 RHS。将“每状态 R 个 RHS”改成“每个事件更新后的矩阵状态 R 个 RHS；初始矩阵计一次 setup”。在方法表中并列列出 `complete factorizations=25`、`state updates=24`、`linear_solutions=24R`。
2. **明确快照关系（必须补）**：披露基准用打包算法快照，提供研究分支 commit、各源文件 SHA-256 与脚本。图注明确该 Node 核心 benchmark 不依赖完整 UI/engine。
3. **拆分论文实证层次（必须改）**：主文 Python 单节点、1–7 轮 JavaScript 预置电路与第八轮 synthetic kernel 三类实验各自列环境、模型和数据文件；不要放入单一趋势表。统一标示“本 PWL 算例/该脚本/该平台”。
4. **补齐主文 Python 复现材料（投稿前门槛）**：目前 ZIP 内容清单中可见 Node 基准、JS 算法快照及 CSV/图像，但未见主文提及的 Python reproduction/mode scripts 和 RMSE 输出；提供可独立运行的代码、依赖锁/版本及输出校验摘要，或提供公开不可变存档。
5. **准确描述 RHS 跨平台重复**：RHS=1 的附加批次为 3 批；RHS=32 只有两个完整 128 阶批次，第三批缺失。将原文“方向在这几批一致”限于实际完成批次。本次 Windows 复跑可作为补充性独立平台证据，不补算进 Node22/Linux 统计。
6. **保留失败和回退数据**：正文保留桥式阈值 1e−8 的毫伏漂移、1e−6 guard 的回退和预测续流大尖峰；避免仅展示平均误差或求逆次数减少。
7. **终稿书目核验**：核对 Ma 等与 2026 Electronics 文章的作者、期卷页/文章号、出版状态、可访问版本与实际相关性。现有第八轮技术附录也明确建议复核相关信息。

## 八、论文主张总表

### 已证实

- 式 (8.1) 单支路导纳印记的 `Δg aaᵀ` 矩阵恒等式；接地支路省略参考端项。
- 式 (8.2) Sherman–Morrison 精确代数公式；实现有分母风险回退，作为工程保护而非定理。
- BE 电容/电感伴随的基本印记与所列电流/电压方向下的表达。
- 单步状态选错时将两套线性方程相减得到的误差恒等式（可逆与同历史量条件下）。
- MNA 中重复理想电压约束造成奇异的 GMIN 反例。
- 指定 Node22/Linux 合成 MNA 基准 CSV 的计时、解差及残差记录与报告表相互一致。
- 指定 Node26/Windows/Ryzen 的 128 阶 RHS=1/32 原脚本复跑验证工作负载敏感的排序反转。

### 部分证实

- 合成稀疏拓扑/稠密运算的阶数与 RHS/矩阵准备计数；主要差别是初始状态 RHS 未执行，论文“每个状态”措辞应精化。
- 研究分支 LU/Rank-1 算法和桥式回退测试；覆盖已有有限电路，而非通用 MNA 拓扑证明。
- HSP 状态预测误差与 BE-end、同 PWL 细网格参考下的四种预置电路结果；细网格不等于连续真解。
- 独立 Python 主文 RC–二极管数值表：论文给出详细方法和参数，当前整合 ZIP 没有相应 Python 脚本/结果文件供本轮实际重跑。
- 单一 Node22 平台下“排序由维数、RHS 复用和低秩安全回退率影响”的方向性观察；并无跨平台通用阈值。

### 尚未验证

- BJT/NMOS 公式的引擎实现与器件行为。
- ngspice 或物理器件瞬态精度对照、硬件波形对照。
- 工业稀疏 MNA、整套 EDA/UI 加速、内存/GC 性能、普遍稳定性/收敛阶。
- 任意近奇异/浮置网络、多个器件任意同时切换时的完备缓存和误差保证。
- 主文 Python 算例报告的实际可重复执行（需原 Python 脚本和依赖环境）。

### 存在错误或需更正

- 将第八轮 benchmark 描述为“每个矩阵状态均解 R 个 RHS”不精确：初始态只做分解/求逆；实际求解为 24R。
- 把打包快照称作“直接使用当前 GitHub 仓库文件”不准确；它是从研究分支取得的算法副本，需标注 commit/哈希。
- 将论文第八轮性能数与主文 Python、电路瞬态、不同平台 Node 时间合并为一个速度或精度结论，属于错误解释。
